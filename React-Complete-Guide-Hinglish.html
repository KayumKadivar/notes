PHASE 1 & 2

Foundation, State & Lists

React ka core concept: UI ko chote reusable hisso (Components) mein todo, aur data (State/Props) ke change hone pe UI ko auto-update hone do.

Components, Props & State

// 1. Component hamesha Capital letter se shuru hota hai function UserCard({ name, age, onPromote }) { // Destructuring Props return ( <div className="card"> {/* class ki jagah className */} <h2>{name}</h2> {/* JS likhne ke liye {} use karo */} <p>Age: {age}</p> <button onClick={onPromote}>Promote</button> </div> ); } // 2. State & Lists (Array Rendering) import { useState } from 'react'; export default function App() { // useState hook: [variableName, setterFunction] const [users, setUsers] = useState([ { id: 1, name: 'Alice', age: 25 }, { id: 2, name: 'Bob', age: 30 } ]); const handlePromote = (id) => { // React state IMMUTABLE hoti hai — direct modify mat karo (users[0].age++) // Hamesha naya array/object return karo map/filter use karke setUsers(prevUsers => prevUsers.map(user => user.id === id ? { ...user, age: user.age + 1 } : user )); }; return ( <div> {users.map(user => ( {/* Har list item ko unique 'key' dena ZAROORI hai! */} <UserCard key={user.id} name={user.name} age={user.age} onPromote={() => handlePromote(user.id)} /> ))} </div> ); }

Kyu `key` zaroori hai?

React Virtual DOM ko compare (Reconciliation) karte waqt `key` se pehchanta hai ki kaunsa element add hua, remove hua ya re-order hua. Agar index ko key banaoge, aur list re-order hogi, toh React galti se galat component ka state maintain kar lega.

PHASE 3 & 4

useEffect & Custom Hooks

React components ko external duniya (APIs, Timers, DOM) se sync karne ke liye useEffect use hota hai. Aur logic ko reuse karne ke liye hum Custom Hooks banate hain.

useEffect & Cleanup (Memory Leak rokna)

useEffect(() => { // 1. Setup function (Component Mount hone pe chalega) const timer = setInterval(() => console.log('Tick'), 1000); const controller = new AbortController(); fetchData(controller.signal); // 2. Cleanup function (Component Unmount hone pe chalega) return () => { clearInterval(timer); // Timer roko controller.abort(); // API request cancel karo }; }, [userId]); // 3. Dependency Array (userId change hone pe wapas chalega)

Custom Hook (useDebounce)

Search input pe har keystroke pe API call rokne ke liye useDebounce ka use karte hain. Yeh logic hum alag file mein nikaal lete hain.

// hooks/useDebounce.js import { useState, useEffect } from 'react'; export function useDebounce(value, delay) { const [debouncedValue, setDebouncedValue] = useState(value); useEffect(() => { const handler = setTimeout(() => { setDebouncedValue(value); }, delay); // Agar delay se pehle value dobara change hui, // toh purana timeout clear ho jayega (Cleanup magic!) return () => clearTimeout(handler); }, [value, delay]); return debouncedValue; } // Component mein use karna: const debouncedSearchTerm = useDebounce(searchTerm, 500); useEffect(() => { searchApi(debouncedSearchTerm) }, [debouncedSearchTerm]);

PHASE 5 & 13

Forms at Scale (RHF + Zod)

useState se har input ko track karna (Controlled components) badhe forms mein app ko slow kar deta hai. React Hook Form (RHF) Uncontrolled inputs use karta hai, jisse performance bachti hai.

React Hook Form + Zod Schema Validation

import { useForm } from 'react-hook-form'; import { zodResolver } from '@hookform/resolvers/zod'; import { z } from 'zod'; // 1. Zod se validation schema banao (Single source of truth) const userSchema = z.object({ email: z.string().email('Invalid email'), password: z.string().min(6, 'Min 6 chars'), age: z.number().min(18, 'Must be 18+') }); export default function SignupForm() { // 2. useForm hook initialize karo const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm({ resolver: zodResolver(userSchema) }); const onSubmit = async (data) => { await apiCall(data); // data perfectly typed aur validated hai }; return ( <form onSubmit={handleSubmit(onSubmit)}> {/* 3. Inputs ko register karo — onChange, onBlur, ref sab auto handle hoga */} <input {...register('email')} placeholder="Email" /> {errors.email && <p className="error">{errors.email.message}</p>} <input type="password" {...register('password')} placeholder="Password" /> {errors.password && <p className="error">{errors.password.message}</p>} <input type="number" {...register('age', { valueAsNumber: true })} /> <button type="submit" disabled={isSubmitting}> {isSubmitting ? 'Submitting...' : 'Sign Up'} </button> </form> ); }

Phase 13 (Field Arrays): Agar tumhe dynamic lists (e.g. multiple skills add karna) chahiye, toh RHF ka useFieldArray hook use karo, array ko asani se map, append, aur remove kar sakte ho bina performance drop ke.

PHASE 6 & 12

State & Server Data (TanStack Query)

React mein do tarah ka state hota hai: Client State (UI theme, modal open) aur Server State (API data). Client state ke liye Context API best hai, par Server state ke liye TanStack Query (React Query) industry standard hai.

TanStack Query (Data Fetching & Caching)

Yeh apne aap caching, background fetching, aur loading/error states handle karta hai. Redux mein asyc logic likhne se bachata hai.

import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query'; function TodosList() { const queryClient = useQueryClient(); // 1. FETCH (useQuery) — Data laane ke liye const { data: todos, isLoading, isError } = useQuery({ queryKey: ['todos'], // Cache key queryFn: () => axios.get('/todos').then(res => res.data), staleTime: 5 * 60 * 1000 // 5 minute tak data fresh rahega (no refetch) }); // 2. MUTATION (useMutation) — Data create/update/delete karne ke liye const mutation = useMutation({ mutationFn: (newTodo) => axios.post('/todos', newTodo), onSuccess: () => { // Success pe purana cache invalidate karo taaki naya list auto-fetch ho queryClient.invalidateQueries({ queryKey: ['todos'] }); } }); if (isLoading) return <Spinner />; if (isError) return <p>Error loading todos</p>; return ( <div> <button onClick={() => mutation.mutate({ title: 'New Task' })}> {mutation.isPending ? 'Adding...' : 'Add Todo'} </button> <ul>{todos.map(t => <li key={t.id}>{t.title}</li>)}</ul> </div> ); }

PHASE 8 & 9

Internals & Performance

Jab parent component render hota hai, toh saare children bhi default render hote hain. React Fiber aur Virtual DOM fast hain, par kabhi-kabhi heavy components ko optimize karna padta hai.

React.memo, useMemo, useCallback

Hook / UtilityKiske liye hai?Kya karta hai?
React.memoComponentAgar Props change nahi hue, toh Component ko re-render hone se roko.
useMemoValue / Array / ObjHeavy calculation ka result cache karta hai. Jab tak deps same hain, function wapas run nahi hoga.
useCallbackFunctionFunction ko cache karta hai, taaki har render pe naya function refernce na bane. (Varna React.memo toot jayega)
import { memo, useState, useCallback, useMemo } from 'react'; // 1. React.memo: Child tab tak render nahi hoga jab tak text ya onClick change na ho const ChildButton = memo(({ text, onClick }) => { console.log('Child render:', text); return <button onClick={onClick}>{text}</button>; }); function Parent() { const [count, setCount] = useState(0); const [theme, setTheme] = useState('light'); // 2. useCallback: Function ka reference same rakho har render mein const increment = useCallback(() => { setCount(c => c + 1); }, []); // Empty array = function life bhar same rahega // 3. useMemo: Heavy calculations roko const expensiveValue = useMemo(() => { let total = 0; for (let i=0; i<10000000; i++) total += i; return total; }, []); // Sirf pehli baar calculate hoga return ( <div> <h1>Count: {count} - Theme: {theme}</h1> <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}> Toggle Theme </button> {/* Theme change hone pe ChildButton re-render NAHI hoga kyunki uske props (increment fn) cache ho chuke hain! */} <ChildButton text="Increment Count" onClick={increment} /> </div> ); }

PHASE 14

Testing: Vitest, RTL & MSW

Testing sirf code likhna nahi hai, yeh confidence hai. Rule: Implementation details test mat karo (e.g. useState call hua?), balki User Behavior test karo (e.g. Button dabane pe error aaya?).

14.1 Component Test (RTL)

React Testing Library (RTL) se hum components ko waise hi test karte hain jaise user interact karta hai.

// src/components/__tests__/Modal.test.jsx import { describe, it, expect, vi } from 'vitest'; import { render, screen, fireEvent } from '@testing-library/react'; import userEvent from '@testing-library/user-event'; import Modal from '../Modal'; describe('Modal Component', () => { it('renders content when open', () => { render(<Modal isOpen={true} title="Test Modal">Content</Modal>); // Assertions (jest-dom matchers) expect(screen.getByText('Test Modal')).toBeInTheDocument(); expect(screen.getByText('Content')).toBeInTheDocument(); }); it('calls onClose when Escape is pressed', async () => { const user = userEvent.setup(); const onCloseMock = vi.fn(); // Vitest se mock function render(<Modal isOpen={true} onClose={onCloseMock}>Content</Modal>); await user.keyboard('{Escape}'); // User action simulate karo expect(onCloseMock).toHaveBeenCalledTimes(1); }); });
