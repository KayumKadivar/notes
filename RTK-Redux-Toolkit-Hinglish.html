Redux Kya Hai Aur Kyun?

Jab React app badi hoti hai aur multiple components ek hi data share karte hain — wahan state management ki zaroorat padti hai. Redux usi problem ka solution hai.

1.1 Prop Drilling Problem

Socho App → Layout → Sidebar → UserMenu → Avatar — Avatar ko user ka naam chahiye. Har intermediate component ko props pass karne padte hain chahe unhe zaroorat na ho.

Appuser = { name, role }
Layoutkhud use nahi karta, sirf pass karta hai
Sidebar → UserMenu → Avataraakhir yahan use hota hai!

1.2 Redux Ka Solution

  • Single Source of Truth — ek Store mein poori app ka state
  • Predictable — state sirf dispatch → reducer → new state se change hota hai
  • Time-travel Debugging — DevTools se past state pe jaao
  • No Prop Drilling — koi bhi component seedha store se data le sakta hai
dispatch(action)Kya hua?
ReducerKaise change hoga?
Store → UINew State

1.3 Redux Kab Use Karein?

SituationRedux Chahiye?
Simple to-do, 2-3 components❌ useState kafi hai
Multiple pages, shared state✅ Haan
Cart, notifications, auth✅ Haan
Large team, multiple features✅ Haan

Pro Tip: Plain Redux complex tha. RTK (Redux Toolkit) ne isko simple bana diya — aaj RTK hi "Modern Redux" hai.

Redux Core Concepts

Redux ki 5 building blocks: Store, Action, Reducer, Dispatch, Selector — yeh sab milke predictable state management banate hain.

2.1 The 5 Pillars

ConceptKya HaiAnalogy
StorePoori app ka state ek jagahSchool ka Principal Office
ActionPlain object — kya hua batata haiForm/Request bharna
ReducerPure function — state kaise change hoLibrarian request process karta hai
DispatchAction store tak pahunchanaForm submit karna
SelectorStore se specific data nikalnaATM se balance check karna

2.2 Pure Function & Immutability

Pure Function: Same input → Always same output, no side effects (no API calls, no random values)

Immutability: State ko directly modify mat karo — hamesha naya object return karo

// ❌ WRONG — state mutate karna function badReducer(state, action) { state.count += 1; // direct mutation! return state; // same reference — React ko pata nahi chalega } // ✅ CORRECT — naya object return karo function goodReducer(state = { count: 0 }, action) { if (action.type === 'increment') { return { ...state, count: state.count + 1 }; // naya object! } return state; // default case — zaroori hai! }

Warning: React shallow comparison karta hai. Same reference = no re-render. Isliye hamesha naya object return karo.

MODULE 03

Plain Redux → Redux Toolkit

Plain Redux mein bahut boilerplate tha — RTK ne sab simplify kar diya. Yeh comparison dekhte hain.

3.1 Plain Redux Ki Problems

  • Bahut saara boilerplate — constants, action creators, reducers alag-alag files
  • Manual immutability — nested spread operators likhna mushkil
  • Mutation ka risk — easily galti ho sakti hai
  • Middleware manually install/configure karna padta tha

3.2 RTK — Same Counter, Half Code

// npm install @reduxjs/toolkit react-redux import { createSlice, configureStore } from '@reduxjs/toolkit'; const counterSlice = createSlice({ name: 'counter', // action types ka prefix initialState: { value: 0 }, reducers: { increment(state) { state.value += 1; }, // Immer — safe mutation! decrement(state) { state.value -= 1; }, incrementBy(state, action) { state.value += action.payload; } } }); // Auto-generated action creators: export const { increment, decrement, incrementBy } = counterSlice.actions; // increment() → { type: "counter/increment" } export const store = configureStore({ reducer: { counter: counterSlice.reducer } // Auto: thunk middleware + Redux DevTools! });

configureStore & React Integration

Store setup karna aur React components mein useSelector / useDispatch se connect karna — yeh hai RTK ka production setup.

4.1 Store + Provider Setup

// src/app/store.js import { configureStore } from '@reduxjs/toolkit'; import counterReducer from '../features/counter/counterSlice'; export const store = configureStore({ reducer: { counter: counterReducer, // state.counter }, devTools: process.env.NODE_ENV !== 'production' }); // src/main.jsx import { Provider } from 'react-redux'; import { store } from './app/store'; ReactDOM.createRoot(document.getElementById('root')).render( <Provider store={store}> {/* Context se store available karta hai */} <App /> </Provider> );

4.2 useSelector & useDispatch

import { useSelector, useDispatch } from 'react-redux'; import { increment, decrement, selectCount } from './counterSlice'; function Counter() { // useSelector — store se data padhna // Jab count change ho tabhi re-render hoga const count = useSelector(state => state.counter.value); // useDispatch — actions bhejne ka function const dispatch = useDispatch(); return ( <div> <p>{count}</p> <button onClick={() => dispatch(decrement())}>-</button> <button onClick={() => dispatch(increment())}>+</button> </div> ); }

Interview Fact: useSelector sirf tab re-render karta hai jab selected value change ho (strict equality). Specific fields select karo, poora state nahi — performance ke liye.

createSlice & Immer Deep Dive

createSlice ek hi function mein reducer, action creators, aur action types — teeno generate karta hai. Immer ki wajah se "mutating" code likh sakte ho safely.

5.1 Immer Kaise Kaam Karta Hai

Tumhara Codestate.value += 1 (mutating lagta hai)
Immer DraftEk proxy copy banata hai original state ka
New Immutable Object{ ...state, value: state.value + 1 } — automatically!

5.2 Complete Slice — Auth Example

// features/auth/authSlice.js import { createSlice } from '@reduxjs/toolkit'; const authSlice = createSlice({ name: 'auth', initialState: { user: null, isLoggedIn: false, token: null, error: null }, reducers: { loginSuccess(state, action) { const { user, token } = action.payload; state.user = user; // Immer — direct assign safe hai! state.token = token; state.isLoggedIn = true; state.error = null; }, logout(state) { state.user = null; state.token = null; state.isLoggedIn = false; }, setAuthError(state, action) { state.error = action.payload; // error message store karo } } }); export const { loginSuccess, logout, setAuthError } = authSlice.actions; // Selectors — slice ke saath colocate karo (best practice) export const selectUser = state => state.auth.user; export const selectIsLoggedIn = state => state.auth.isLoggedIn; export default authSlice.reducer;

Important: Ya toh mutate karo (Immer handles), ya explicitly naya object return karo. Dono ek saath mat karo — Immer confuse ho jaata hai.

5.3 extraReducers — Cross-Slice Actions

// Cart slice jo auth slice ke logout ko handle kare import { logout } from '../auth/authSlice'; const cartSlice = createSlice({ name: 'cart', initialState: { items: [], total: 0 }, reducers: { /* cart ke apne actions */ }, extraReducers: (builder) => { // Jab auth slice ka logout dispatch ho — cart bhi clear karo builder.addCase(logout, (state) => { state.items = []; state.total = 0; }); } }); // Ab dispatch(logout()) se auth + cart + notifications — sab clear!

MODULE 06

createAsyncThunk — Async Operations

Reducer pure function hai — API calls nahi kar sakta. createAsyncThunk async operations ke liye middleware provide karta hai — auto pending/fulfilled/rejected states ke saath.

6.1 Async Thunk Flow

dispatch(fetchUsers())Thunk function dispatch kiya
Auto: fetchUsers.pendingloading: true, error: null — spinner dikhao
payloadCreator runs (API call)fetch('/api/users') aur response aata hai
✅ fulfilleddata store, loading false
❌ rejectederror store, loading false

6.2 Complete Example

import { createSlice, createAsyncThunk } from '@reduxjs/toolkit'; // Thunk define karo export const fetchUsers = createAsyncThunk( 'users/fetchAll', // action type prefix async (_, { getState, rejectWithValue }) => { const token = getState().auth.token; // store se token lo const res = await fetch('/api/users', { headers: { Authorization: `Bearer ${token}` } }); if (!res.ok) return rejectWithValue('Fetch fail hua'); return res.json(); // → action.payload in fulfilled } ); // Slice mein handle karo const usersSlice = createSlice({ name: 'users', initialState: { data: [], loading: false, error: null }, reducers: {}, extraReducers: (builder) => { builder .addCase(fetchUsers.pending, (state) => { state.loading = true; state.error = null; }) .addCase(fetchUsers.fulfilled, (state, action) => { state.loading = false; state.data = action.payload; // API response }) .addCase(fetchUsers.rejected, (state, action) => { state.loading = false; state.error = action.payload; // rejectWithValue ka value }); } });

RTK Query — Kya Aur Kyun?

createAsyncThunk se caching, deduplication, auto-refetching manually likhna padta tha. RTK Query yeh sab automatically handle karta hai.

7.1 createAsyncThunk vs RTK Query

FeaturecreateAsyncThunkRTK Query
Caching❌ Manual✅ Automatic
Loading statesManual useStateAuto hooks
Cache invalidation❌✅ Tags system
Deduplication❌✅ Built-in
Auto re-fetchManual✅ Configurable
Optimistic updatesComplex✅ onQueryStarted
PollingManual setInterval✅ pollingInterval
Code amountZyadaBahut Kam

Rule: Standard CRUD API → RTK Query. Complex business logic, non-REST operations → createAsyncThunk.

7.2 RTK Query Cache Flow

useGetPostsQuery() — pehli baarCache empty → GET /posts request hoti hai
Response → Cache mein store"getPosts(undefined)" → { data: [...] }
Dobara same queryCache se serve — NO network request!
Mutation (create/update/delete)invalidatesTags → cache invalid → auto re-fetch

createApi & fetchBaseQuery

RTK Query ka core setup — ek createApi call mein sab endpoints, tags, aur auto-generated hooks milte hain.

8.1 Complete createApi Setup

// src/features/api/apiSlice.js import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react'; // Note: '/react' suffix — hooks auto-generate ke liye zaroori! export const apiSlice = createApi({ reducerPath: 'api', // store mein state ka path (unique hona chahiye) baseQuery: fetchBaseQuery({ baseUrl: 'https://jsonplaceholder.typicode.com', // Har request mein common headers add karo prepareHeaders: (headers, { getState }) => { const token = getState().auth.token; if (token) headers.set('Authorization', `Bearer ${token}`); return headers; } }), tagTypes: ['Post', 'User'], // cache invalidation ke liye tags declare karo endpoints: (builder) => ({ // ---- QUERIES (GET requests) ---- getPosts: builder.query({ query: () => '/posts', providesTags: (result) => result ? [...result.map(({ id }) => ({ type: 'Post', id })), { type: 'Post', id: 'LIST' }] : [{ type: 'Post', id: 'LIST' }] }), getPostById: builder.query({ query: (id) => `/posts/${id}`, providesTags: (result, error, id) => [{ type: 'Post', id }] }), // ---- MUTATIONS (POST/PUT/DELETE) ---- createPost: builder.mutation({ query: (body) => ({ url: '/posts', method: 'POST', body }), invalidatesTags: [{ type: 'Post', id: 'LIST' }] // Create ke baad list auto re-fetch hogi! }), updatePost: builder.mutation({ query: ({ id, ...body }) => ({ url: `/posts/${id}`, method: 'PUT', body }), invalidatesTags: (result, error, { id }) => [{ type: 'Post', id }] }), deletePost: builder.mutation({ query: (id) => ({ url: `/posts/${id}`, method: 'DELETE' }), invalidatesTags: [{ type: 'Post', id: 'LIST' }] }) }) }); // Auto-generated hooks export karo export const { useGetPostsQuery, useGetPostByIdQuery, useCreatePostMutation, useUpdatePostMutation, useDeletePostMutation } = apiSlice;

8.2 Store Mein Register Karna

// src/app/store.js — middleware add karna ZAROORI hai! import { configureStore } from '@reduxjs/toolkit'; import { apiSlice } from '../features/api/apiSlice'; export const store = configureStore({ reducer: { [apiSlice.reducerPath]: apiSlice.reducer, // "api" key }, middleware: (getDefault) => getDefault().concat(apiSlice.middleware) // caching + invalidation handles! });

Warning: apiSlice.middleware add karna bhoologe toh caching, tags, polling — kuch kaam nahi karega!

Mutations & Cache Invalidation

providesTags aur invalidatesTags — RTK Query ka sabse powerful feature. Mutation ke baad related queries automatically re-fetch hoti hain.

10.1 Tags Flow Diagram

getPosts — providesTags: ['Post/LIST', 'Post/1', 'Post/2'...]Yeh query 'Post' tag ka data provide karti hai
createPost mutation — invalidatesTags: ['Post/LIST']Create ke baad 'Post/LIST' tag invalid karo
RTK Query: 'Post/LIST' provide karne wali query kaun hai?→ getPosts!
getPosts Automatically Re-Fetch ✅Naya post list mein automatically aayega!

10.2 useMutation Hook — Component Mein

function CreatePostForm() { const [createPost, { isLoading, isSuccess, isError, error }] = useCreatePostMutation(); const handleSubmit = async (formData) => { try { // .unwrap() — success pe data deta hai, error pe throw karta hai const result = await createPost(formData).unwrap(); console.log('Created:', result); } catch (err) { console.error('Failed:', err); } }; return ( <button disabled={isLoading} onClick={() => handleSubmit(data)}> {isLoading ? 'Creating...' : 'Create Post'} </button> ); }

10.3 Optimistic Updates

// Server response ka wait mat karo — pehle UI update karo updatePost: builder.mutation({ query: ({ id, ...body }) => ({ url: `/posts/${id}`, method: 'PUT', body }), async onQueryStarted({ id, ...patch }, { dispatch, queryFulfilled }) { // Cache immediately patch karo (optimistic update) const patchResult = dispatch( apiSlice.util.updateQueryData('getPosts', undefined, (draft) => { const post = draft.find(p => p.id === id); if (post) Object.assign(post, patch); // Immer draft safe! }) ); try { await queryFulfilled; // Server success — done! } catch { patchResult.undo(); // Server fail → rollback! } } })

MODULE 12

Interview Questions — Redux & RTK

Most commonly asked questions — concept + code dono taraf se. Yeh answers memorize mat karo, samjho.

12.1 Redux Fundamentals

Q1: Redux ke 3 core principles kya hain?

1) Single Source of Truth — ek store. 2) State is Read-Only — sirf actions se change. 3) Pure Reducers — same input → same output, no side effects.

Q2: Reducer mein direct mutation kyun nahi karte?

React shallow comparison karta hai. Agar same reference return ho, React ko change pata nahi chalta aur re-render nahi hota. Naya object return karna zaroori hai.

Q3: createSlice kya auto-generate karta hai?

Teen cheezein: (1) Reducer function, (2) Action creators — har reducer ke liye ek, (3) Action types — sliceName/reducerName format mein.

Q4: extraReducers kab use karte hain?

Jab ek slice ko doosre slice ke action par react karna ho. Example: logout dispatch hone pe cart bhi clear karo — cart slice auth ke logout ko extraReducers mein handle karta hai.

Q5: Immer kya hai aur kaise kaam karta hai?

Immer draft state banata hai. Mutations draft pe hoti hain. Immer internally naya immutable object produce karta hai. RTK mein createSlice ke andar automatically use hota hai.

12.2 RTK Query Questions

Q6: isLoading aur isFetching mein kya fark hai?

isLoading = sirf pehli baar (cache empty). isFetching = koi bhi re-fetch, background bhi. Cache available hone pe isLoading false hota hai, isFetching true.

Q7: providesTags aur invalidatesTags ka relationship?

Query batata hai kya data provide karta hai (providesTags). Mutation ke baad kaunse tags invalid karne hain (invalidatesTags). Match hone pe woh queries auto re-fetch hoti hain.

Q8: .unwrap() kya karta hai?

Mutation result ko normal promise mein convert karta hai. Success pe data return, error pe throw. try/catch se cleanly handle kar sakte ho.

Q9: Optimistic updates kaise implement karein?

onQueryStarted mein api.util.updateQueryData() se cache patch karo. Server success pe permanent. Fail pe patchResult.undo() se rollback.

Q10: RTK Query middleware store mein kyun add karna zaroori hai?

Middleware caching lifecycle, polling, cache invalidation, refetching sab handle karta hai. Bina middleware ke kuch bhi kaam nahi karega.
