TOPIC 01

SQL Kya Hai?

SQL (Structured Query Language) woh standard language hai jisse hum relational databases se baat karte hain — data store, retrieve, update aur manage karne ke liye.

1.1 Databases Kyun Chahiye?

Socho tumhare paas ek school ka register hai jisme students ke naam, roll number aur marks likhe hain — yeh ek manual database hai. Real apps mein yehi kaam ek proper database karta hai, bas fast aur reliable tarike se.

  • Bada data organized tarike se store hota hai
  • Data accurate, consistent aur secure rehta hai
  • Fast retrieval aur analysis possible hota hai
  • Multiple users ek saath real-time use kar sakte hain

1.2 DBMS vs RDBMS

DBMSRDBMS
Data files/simple structures mein store hota haiData tables mein store hota hai
Relationships limited hoti hainPrimary & Foreign Keys se relations bante hain
Data integrity kam hoti haiConstraints se better integrity milti hai
e.g., File System, XMLe.g., MySQL, PostgreSQL, SQL Server, Oracle

1.3 SQL Kaha Use Hota Hai

  • Web applications aur banking/finance systems
  • E-commerce, data analysis & reporting
  • QA automation (test data) aur DevOps monitoring
DatabaseKyu Popular Hai
MySQLOpen-source, web applications mein widely used
PostgreSQLAdvanced open-source, reliability aur performance ke liye jana jaata hai
SQL ServerMicrosoft ka enterprise-grade relational database

Interview Fact: SQL "S-Q-L" ya "Sequel" dono tarike se bola jaata hai — dono pronunciations sahi maane jaate hain.

Pro Tip: SQL ek declarative language hai — tum database ko batate ho WHAT chahiye, HOW karna hai woh database khud decide karta hai.

TOPIC 03

SELECT Statement

SELECT ek ya zyada tables se data retrieve karne ke liye use hota hai — SQL ka sabse zyada use hone wala statement.

3.1 Basic SELECT & Multiple Columns

Saari rows/columns chahiye to * use karo, warna sirf zaroori columns specify karo:

SELECT * FROM Employees; -- specific columns — better practice SELECT EmpID, Name, Salary FROM Employees;

3.2 DISTINCT

Sirf unique values chahiye ho to DISTINCT lagao:

SELECT DISTINCT Department FROM Employees;

3.3 LIMIT / TOP & Aliases

-- MySQL, PostgreSQL, SQLite SELECT Name, Salary FROM Employees LIMIT 5; -- SQL Server SELECT TOP 5 Name, Salary FROM Employees; -- alias — temporary readable name SELECT Name AS EmployeeName, Salary AS MonthlySalary FROM Employees;

Note: LIMIT/TOP ka syntax database ke hisaab se alag hota hai, functionality same rehti hai.

3.4 SELECT * — Best Practice Nahi Hai

  • Production mein SELECT * avoid karo — unnecessary columns retrieve hote hain
  • Network traffic aur memory usage badh jaata hai
  • Naya column add hone par query break bhi ho sakti hai

Pro Tip: Hamesha wahi columns select karo jo actually chahiye — better performance, better security, better maintainability.

Interview Fact: SELECT statement SQL interviews mein sabse zyada poochha jaane wala topic hai.

Filtering Data — WHERE

WHERE clause rows ko filter karta hai ek ya zyada conditions ke basis par.

4.1 AND / OR / NOT

OperatorBehaviourExample
ANDDono conditions true honi chahiyeWHERE Salary > 50000 AND Dept = 'IT'
ORKoi ek bhi condition true ho to chalegaWHERE Dept = 'IT' OR Dept = 'HR'
NOTResult ko reverse karta haiWHERE NOT Dept = 'IT'

4.2 BETWEEN, IN, LIKE, IS NULL

-- BETWEEN: range ke andar values (inclusive) SELECT * FROM Employees WHERE Salary BETWEEN 40000 AND 80000; -- IN: list mein se koi bhi value match ho SELECT * FROM Employees WHERE Dept IN ('IT', 'HR', 'Finance'); -- LIKE: pattern search — % = kitne bhi characters, _ = ek character SELECT * FROM Employees WHERE Name LIKE 'A%'; -- NULL check: IS NULL / IS NOT NULL (= ya <> kabhi kaam nahi karega) SELECT * FROM Employees WHERE ManagerID IS NULL;

4.3 Quick Reference

TOPIC 05

Sorting & Limiting

Yeh clauses result set ko sort karte hain aur return hone waali rows ki number control karte hain.

5.1 ORDER BY — ASC vs DESC

SELECT Name, Salary FROM Employees ORDER BY Salary; -- default ASC (smallest to largest) SELECT Name, Salary FROM Employees ORDER BY Salary DESC; -- largest to smallest

ORDER BY hamesha query ke end mein use hota hai, aur agar isko skip kiya to rows ka order guaranteed nahi hota.

5.2 LIMIT, OFFSET, TOP & FETCH FIRST

-- MySQL / PostgreSQL / SQLite SELECT Name, Salary FROM Employees ORDER BY Salary DESC LIMIT 5 OFFSET 10; -- 10 skip, phir 5 rows -- SQL Server SELECT TOP 5 Name, Salary FROM Employees ORDER BY Salary DESC; -- ANSI standard (DB2, Oracle, PostgreSQL v13+, SQL Server with OFFSET) SELECT Name, Salary FROM Employees ORDER BY Salary DESC FETCH FIRST 5 ROWS ONLY;
KeywordKaam
LIMITReturn hone waali rows ki count restrict karta hai
OFFSETPehle N rows skip karta hai
TOPSELECT ke turant baad rows count specify karta hai (SQL Server)

Pro Tip: Consistent results ke liye LIMIT/TOP/FETCH ke saath hamesha ORDER BY use karo.

Interview Fact: ORDER BY ke bina rows ka order database engine par depend karta hai — guaranteed nahi hota.

TOPIC 06

Aggregate Functions

Aggregate functions values ke ek set par calculation karte hain aur ek single result return karte hain.

6.1 Overview

FunctionKya Karta Hai
COUNT()Rows ki number count karta hai
SUM()Numeric values ka total sum return karta hai
AVG()Numeric values ka average return karta hai
MIN()Sabse chhoti value return karta hai
MAX()Sabse badi value return karta hai

6.2 Practical Examples

SELECT COUNT(*) FROM Employees; -- 5 SELECT SUM(Salary) FROM Employees; -- 295000 SELECT AVG(Salary) FROM Employees; -- 59000.00 SELECT MIN(Salary) FROM Employees; -- 45000 SELECT MAX(Salary) FROM Employees; -- 70000

COUNT(*) NULL values sameet saari rows count karta hai; COUNT(column) sirf non-NULL values count karta hai. SUM/AVG/MIN/MAX NULL values ko ignore karte hain.

6.3 GROUP BY Ke Saath

SELECT Department, AVG(Salary) AS AvgSalary FROM Employees GROUP BY Department;

Pro Tip: Aggregate functions GROUP BY, HAVING aur JOINs ke saath combine karke real-world analytics banti hai.

Interview Fact: Reporting aur analytics queries mein aggregate functions bohot common poochhe jaate hain.

TOPIC 07

GROUP BY & HAVING

GROUP BY same values waali rows ko summary rows mein group karta hai. HAVING un groups (aggregated results) ko filter karta hai.

7.1 GROUP BY vs HAVING

WHEREHAVING
Grouping se pehle rows filter karta haiGrouping ke baad groups filter karta hai
Individual rows par kaam karta haiAggregate values par kaam karta hai
Aggregate functions use nahi kar sakteAggregate functions ke saath use hota hai

7.2 Grouping Rules

  • SELECT ka har non-aggregate column GROUP BY mein hona chahiye
  • WHERE mein aggregate functions use nahi kar sakte
  • Column aliases HAVING mein use nahi ho sakte — full expression likhna padta hai
-- Valid SELECT DeptID, COUNT(*) AS EmpCount FROM Employees GROUP BY DeptID HAVING COUNT(*) > 3; -- Invalid — Name na GROUP BY mein hai, na aggregate ke andar SELECT DeptID, Name, COUNT(*) FROM Employees GROUP BY DeptID;

7.3 Interview Example

SELECT DeptID, SUM(Salary) AS TotalSalary FROM Employees GROUP BY DeptID HAVING SUM(Salary) > 60000 ORDER BY TotalSalary DESC;

Yeh query un departments ko dikhati hai jinki total salary 60000 se zyada hai — sorted highest first.

Pro Tip: Rows early reduce karne ke liye WHERE pehle apply karo, HAVING sirf aggregate conditions ke liye use karo.

SQL Joins

Joins do ya zyada tables ki rows ko unke beech ke related column ke basis par combine karte hain.

8.1 Sample Tables

Table A (Employees) aur Table B (Departments) ko A.DeptID = B.DeptID se join karte hain.

8.2 Types of Joins

INNER JOIN

RIGHT JOIN

FULL OUTER JOIN
Dono tables ki saari rows, jaha match nahi wahan NULL
Join TypeSyntax

Interview Fact: Joins SQL ke sabse important aur sabse zyada poochhe jaane wale concepts mein se hain.

Self Join & UNION

Self Join ek table ko khud ke saath join karta hai. Set operators do ya zyada SELECT statements ke results combine karte hain.

9.1 Self Join

Hierarchical data (jaise Manager-Employee) compare karne ke liye useful hai. Alias (E, M) mandatory hai.

SELECT E.Name AS Employee, M.Name AS Manager FROM Employees E LEFT JOIN Employees M ON E.ManagerID = M.EmpID;

UNION ALL
Saari rows dono se (duplicates included)
INTERSECT

EXCEPT / MINUS
A ki rows jo B mein nahi hain

TOPIC 10

Subqueries

Subquery (inner query) ek query ke andar doosri query hoti hai — inner query pehle run hoti hai.

10.1 Single-Row vs Multi-Row

-- Single-row: exactly ek value return karti hai SELECT Name, Salary FROM Employees WHERE Salary > (SELECT AVG(Salary) FROM Employees); -- Multi-row: IN / NOT IN / ANY / ALL ke saath SELECT Name FROM Employees WHERE DeptID IN (SELECT DeptID FROM Departments WHERE Location = 'Ahmedabad');

10.2 Correlated Subquery & EXISTS

Correlated subquery outer query ke columns ko refer karti hai aur outer query ki har row ke liye ek baar chalti hai.

SELECT E1.Name, E1.Salary FROM Employees E1 WHERE E1.Salary > ( SELECT AVG(E2.Salary) FROM Employees E2 WHERE E2.DeptID = E1.DeptID ); -- EXISTS — NULLs ke saath IN se zyada reliable SELECT Name FROM Employees E WHERE EXISTS (SELECT 1 FROM Departments D WHERE D.DeptID = E.DeptID);

10.3 IN vs EXISTS

AspectINEXISTS
Kaam kaise karta haiValue ko ek list se compare karta haiRows ka existence check karta hai
NULL handlingUnexpected result de sakta haiNULLs se affect nahi hota
Best forChhote result setsBade result sets

Pro Tip: Subqueries ko pehle alag se test karo, phir outer query ke andar use karo. Correlated subqueries slow ho sakti hain — jahan possible ho JOINs use karo.

Interview Fact: Subqueries SQL interviews ka favourite topic hain — alag-alag datasets par practice zaroor karo.

TOPIC 12

CASE Statement

CASE statement conditional logic perform karta hai aur conditions ke basis par value return karta hai.

12.1 Simple & Searched CASE

-- Searched CASE — boolean conditions evaluate karta hai SELECT Name, Salary, CASE WHEN Salary >= 70000 THEN 'High' WHEN Salary BETWEEN 50000 AND 69999 THEN 'Medium' ELSE 'Low' END AS SalaryLevel FROM Employees;

12.2 NULL Handling — IFNULL / COALESCE

-- IFNULL (MySQL) SELECT Name, IFNULL(Email, 'No Email') AS Email FROM Employees; -- COALESCE (ANSI SQL — multiple columns check karta hai) SELECT Name, COALESCE(Email, Phone, 'No Contact') AS Contact FROM Employees;

Yaad Rakho: = NULL ya <> NULL kabhi kaam nahi karega — hamesha IS NULL / IS NOT NULL use karo.

Pro Tip: Multiple columns mein NULL check karna ho to COALESCE use karo, aur = / <> NULL ke bajaye IS NULL / IS NOT NULL prefer karo.

Interview Fact: CASE aur COALESCE interviews mein conditional logic aur NULL handling test karne ke liye frequently poochhe jaate hain.

DDL Commands

DDL (Data Definition Language) commands database objects ko define, modify aur manage karte hain.

13.1 CREATE & ALTER

CREATE TABLE Employees ( EmpID INT PRIMARY KEY, Name VARCHAR(50) NOT NULL, Salary DECIMAL(10,2) ); ALTER TABLE Employees ADD Email VARCHAR(100); ALTER TABLE Employees DROP COLUMN Email; ALTER TABLE Employees RENAME COLUMN Name TO FullName;

13.2 DROP, TRUNCATE & RENAME

CommandKya Karta Hai
DROP TABLE Employees;Table ko structure sameet permanently remove karta hai
TRUNCATE TABLE Employees;Saari rows remove karta hai, table structure intact rehta hai
ALTER TABLE Employees RENAME TO Staff;Table ka naam badalta hai

Careful: TRUNCATE DELETE se fast hota hai lekin kuch DBMS mein rollback nahi ho sakta — DROP ya TRUNCATE se pehle hamesha backup lo.

Pro Tip: Saari rows remove karni ho to DELETE ke bajaye TRUNCATE prefer karo — faster hota hai.

Interview Fact: Zyada tar database systems mein DDL commands implicit COMMIT cause karte hain.

TOPIC 14

DML & TCL Commands

DML (Data Manipulation Language) data manipulate karta hai. TCL (Transaction Control Language) transactions manage karta hai.

14.1 INSERT, UPDATE, DELETE

INSERT INTO Employees (EmpID, Name, Salary, DeptID) VALUES (101, 'Alice', 60000, 1); UPDATE Employees SET Salary = 65000 WHERE EmpID = 101; DELETE FROM Employees WHERE EmpID = 101;

WHERE clause ke bina UPDATE/DELETE saari rows ko affect karte hain — hamesha WHERE lagana mat bhulo.

14.2 COMMIT, ROLLBACK, SAVEPOINT

COMMIT; -- current transaction ke saare changes permanently save karta hai ROLLBACK; -- last COMMIT ke baad ke changes revert karta hai SAVEPOINT sp1; UPDATE Employees SET Salary = 70000 WHERE EmpID = 101; ROLLBACK TO sp1; -- sirf sp1 tak revert

Pro Tip: Pehle chhote datasets par test karo, COMMIT tabhi karo jab pura sure ho. SAVEPOINT complex transactions ko step-by-step safe banata hai.

Interview Fact: DML data ko affect karta hai, TCL sirf transactions control karta hai — data ko nahi.

15.1 Constraints

CREATE INDEX idx_emp_name ON Employees(Name); -- MySQL EmpID INT AUTO_INCREMENT PRIMARY KEY -- SQL Server EmpID INT IDENTITY(1,1) PRIMARY KEY

Pro Tip: WHERE, JOIN aur ORDER BY mein use hone waale columns par indexes lagao — application-side validation bhi DEFAULT/CHECK se reduce hoti hai.

Interview Fact: Real-world database design mein constraints aur indexes dono crucial hote hain.

TOPIC 16

Views & Stored Objects

Stored objects database objects hote hain jo logic store karte hain — security, reusability aur performance improve karne ke liye.

16.1 Views

View ek SELECT query par based virtual table hai — data physically store nahi hota.

CREATE VIEW v_emp_dept AS SELECT e.EmpID, e.Name, d.DeptName FROM Employees e JOIN Departments d ON e.DeptID = d.DeptID WHERE e.Status = 'Active';

16.2 Stored Procedures & Functions

-- Stored Procedure — SQL statements ka reusable block CREATE PROCEDURE GetEmployeesByDept (IN p_dept_id INT) BEGIN SELECT EmpID, Name, Salary FROM Employees WHERE DeptID = p_dept_id; END; -- CALL GetEmployeesByDept(10); -- Function — hamesha ek value return karta hai CREATE FUNCTION GetTotalSalary(p_emp_id INT) RETURNS DECIMAL(10,2) BEGIN RETURN (SELECT Salary FROM Employees WHERE EmpID = p_emp_id); END;

16.3 Triggers & Sequences

Trigger automatically execute hota hai jab table par ek specified event (INSERT/UPDATE/DELETE) hoti hai. Sequences unique numeric values generate karti hain.

CREATE TRIGGER trg_emp_audit AFTER INSERT ON Employees FOR EACH ROW BEGIN INSERT INTO EmpAudit (EmpID, ActionDate, Action) VALUES (NEW.EmpID, CURRENT_TIMESTAMP, 'INSERT'); END;

Pro Tip: Security aur simplicity ke liye Views, business logic ke liye Stored Procedures, aur unique IDs ke liye Sequences/AUTO_INCREMENT use karo.

Interview Fact: Triggers, Procedures aur View vs Table differences employers ke favourite interview topics hain.

TOPIC 17

Window Functions

Window functions rows ke ek related set par calculation karte hain, GROUP BY ki tarah unhe collapse kiye bina.

17.1 OVER(), PARTITION BY, ORDER BY

function() OVER ( [PARTITION BY column_list] [ORDER BY column_list] )

PARTITION BY rows ko independent groups mein split karta hai (GROUP BY jaisa, par rows collapse nahi hoti). ORDER BY har partition ke andar rows ka order define karta hai.

17.2 ROW_NUMBER, RANK, DENSE_RANK

SELECT EmpID, Name, Salary, ROW_NUMBER() OVER (PARTITION BY DeptID ORDER BY Salary DESC) AS rn, RANK() OVER (PARTITION BY DeptID ORDER BY Salary DESC) AS rnk, DENSE_RANK() OVER (PARTITION BY DeptID ORDER BY Salary DESC) AS drnk FROM Employees;

RANK() ties ke baad ek gap chhod deta hai (1,2,2,4); DENSE_RANK() gap nahi chhodta (1,2,2,3).

17.3 LEAD() & LAG()

SELECT EmpID, Salary, LEAD(Salary, 1) OVER (PARTITION BY DeptID ORDER BY Salary DESC) AS NextSal, LAG(Salary, 1) OVER (PARTITION BY DeptID ORDER BY Salary DESC) AS PrevSal FROM Employees;

LEAD() next row ki value laata hai, LAG() previous row ki — trend analysis aur comparisons ke liye bohot useful.

Pro Tip: Deterministic results ke liye window functions ke saath hamesha ORDER BY use karo.

Interview Fact: Window functions rankings, running totals aur "gaps & islands" jaise problems ke liye frequently poochhe jaate hain.
