TOPIC 01

Routing Kya Hai? (SPA)

Traditional websites mein naye page pe jaane par poora page reload hota hai. React ek SPA (Single Page Application) hai — page reload nahi hota, sirf andar ka component change hota hai.

1.1 MPA vs SPA

FeatureMulti-Page App (Old)Single Page App (React)
Page transitionFull browser reload hota haiInstant (sirf DOM update hota hai)
SpeedSlow — har baar HTML server se aata haiFast — sirf JSON data fetch hota hai
StatePage refresh pe state loss ho jaati haiState persist rehti hai navigation ke beech
RoutingServer handle karta haiClient (Browser) handle karta hai

1.2 React Router v6.4+ Updates

Pehle hum <BrowserRouter> ke andar components wrap karte the. v6.4 se naya data API aaya hai (createBrowserRouter). Ab routing JavaScript objects/array ke through define hoti hai. Yeh naya pattern data loaders aur actions ko support karta hai.

Old Way (v5 / early v6)<Route path="/" element={<App/>} />
New Way (v6.4+){ path: "/", element: <App/> }

Pro Tip: Naye projects mein hamesha createBrowserRouter use karo. Yeh nayi Data APIs (loaders, actions, fetchers) ko enable karta hai jo React 18 aur aage ke liye best hain.

TOPIC 02

Modern Router Setup (v6.4+)

Sabse pehle library install karni hai aur apna routing object banana hai. Uske baad usko app mein inject karna hai.

2.1 Installation & Basic Setup

# Terminal mein install karo: npm install react-router-dom
// src/main.jsx — Ya entry file mein import React from 'react'; import ReactDOM from 'react-dom/client'; import { createBrowserRouter, RouterProvider } from 'react-router-dom'; // Import your page components import Home from './pages/Home'; import About from './pages/About'; import Contact from './pages/Contact'; import NotFound from './pages/NotFound'; // 1. Router configure karo — Objects ka array const router = createBrowserRouter([ { path: '/', element: <Home />, errorElement: <NotFound />, // Agar URL exist nahi karta toh yeh dikhega }, { path: '/about', element: <About />, }, { path: '/contact', element: <Contact />, } ]); // 2. App ko RouterProvider mein wrap karo ReactDOM.createRoot(document.getElementById('root')).render( <React.StrictMode> <RouterProvider router={router} /> </React.StrictMode> );

2.2 Common Mistake: errorElement

Agar errorElement root pe define nahi karoge, toh invalid URL pe React default (ugly) error screen dikhayega jo development mein red screen hoti hai. Isliye root path pe hamesha ek 404 page lagana zaroori hai.

TOPIC 03

Navigation: Link vs NavLink vs useNavigate

React mein <a href="..."> use nahi karte! Kyun? Kyunki woh poora page reload kar dega (SPA break ho jayega). Iski jagah React Router ke components aur hooks use hote hain.

3.1 Link (Simple Navigation)

import { Link } from 'react-router-dom'; function Navbar() { return ( <nav> {/* ❌ DON'T do this: <a href="/about">About</a> */} {/* ✅ DO this: */} <Link to="/">Home</Link> <Link to="/about">About Us</Link> <Link to="/contact">Contact</Link> </nav> ); }

3.2 NavLink (Active Styling)

NavLink bilkul Link jaisa hai, par usko pata hota hai ki woh "active" hai ya nahi. Navigation menus/sidebars ke liye best hai.

import { NavLink } from 'react-router-dom'; function Sidebar() { return ( <div> <NavLink to="/dashboard" className={({ isActive }) => (isActive ? 'nav-active' : 'nav-inactive')} style={({ isActive }) => ({ color: isActive ? 'red' : 'black' })} > Dashboard </NavLink> </div> ); }

3.3 useNavigate (Programmatic Navigation)

Jab kisi button click pe, form submit hone ke baad, ya API response ke baad navigate karna ho.

import { useNavigate } from 'react-router-dom'; function LoginForm() { const navigate = useNavigate(); const handleSubmit = async (e) => { e.preventDefault(); await loginApi(); // API call ki navigate('/dashboard'); // ✅ Success ke baad Dashboard bhejo // Back jaane ke liye: // navigate(-1); }; return <button onClick={handleSubmit}>Login</button>; }

TOPIC 04

Dynamic Routes & URL Params

E-commerce mein har product ke liye alag page nahi banate. Ek hi "Product Details" page hota hai, bas URL mein ID badalti hai. Isey Dynamic Routing kehte hain.

4.1 Route Parameter Setup (/:id)

// main.jsx mein route setup: const router = createBrowserRouter([ { path: '/products', element: <ProductsList /> }, // URL mein colon (:) ka matlab hai yeh part dynamic/variable hai { path: '/products/:id', element: <ProductDetails /> } ]); // Valid URLs: /products/123, /products/apple-watch

4.2 useParams() — ID Extract Karna

Component ke andar URL ka woh variable (ID) padhne ke liye useParams hook use hota hai.

import { useParams } from 'react-router-dom'; function ProductDetails() { // Hook wahi name return karega jo route mein colon (:) ke baad tha const { id } = useParams(); // Agar URL /products/99 hai, toh id = "99" // Ab is ID se API call kar sakte hain: // const { data } = useQuery(`/api/products/${id}`); return <h1>Showing details for Product ID: {id}</h1>; }

4.3 useSearchParams() — Query Params (?key=value)

Search filters, pagination, ya sorting ke liye hum URL ke aakhir mein query parameters lagate hain. (e.g. /products?category=shoes&page=2)

import { useSearchParams } from 'react-router-dom'; function ProductsList() { // Yeh hook useState ki tarah [state, setter] return karta hai const [searchParams, setSearchParams] = useSearchParams(); // Value padhna: const category = searchParams.get('category') || 'all'; const page = searchParams.get('page') || 1; // Value set karna (URL update karna): const handleFilter = (newCategory) => { setSearchParams({ category: newCategory, page: 1 }); // URL ban jayega: /products?category=electronics&page=1 }; return ( <div> <h3>Current Category: {category}</h3> <button onClick={() => handleFilter('shoes')}>Shoes</button> </div> ); }

TOPIC 05

Layouts & Nested Routes (<Outlet />)

Har page mein Navbar aur Footer alag-alag import karne ki zaroorat nahi hai. Hum ek Parent Layout bana sakte hain jo fixed rahega, aur beech ka content URL ke hisaab se change hoga.

5.1 Router Object mein Nesting

const router = createBrowserRouter([ { path: '/', element: <MainLayout />, // Parent Route errorElement: <ErrorPage />, children: [ // Child Routes { path: '', element: <Home /> }, // '/' { path: 'about', element: <About /> }, // '/about' { path: 'contact', element: <Contact /> } // '/contact' ] }, { path: '/dashboard', element: <DashboardLayout />, // Alag layout! children: [ { path: '', element: <DashHome /> }, { path: 'settings', element: <Settings /> } ] } ]);

5.2 The Magic of <Outlet />

MainLayout component ko pata hona chahiye ki jo "children" routes humne define kiye hain, unhe kahan render karna hai. Wahan hum <Outlet /> lagate hain.

// layouts/MainLayout.jsx import { Outlet } from 'react-router-dom'; import Navbar from '../components/Navbar'; import Footer from '../components/Footer'; function MainLayout() { return ( <div className="app-container"> <Navbar /> {/* Yeh hamesha dikhega */} <main className="content-area"> {/* YAHAN magic hota hai! */} {/* Agar URL /about hai, toh ki jagah aa jayega */} <Outlet /> </main> <Footer /> {/* Yeh hamesha dikhega */} </div> ); }

Pro Tip: <Outlet /> ek placeholder hai child routes ke liye. Isse code repetition khatam ho jaati hai aur layout clean rehta hai.

TOPIC 06

Protected Routes (Auth Guards)

Kuch pages (jaise Profile ya Dashboard) sirf logged-in users ko dikhne chahiye. Agar bina login koi us URL pe jaaye, toh usko Login page pe redirect karna zaroori hai.

6.1 AuthGuard Component Banana

Ek wrapper component banao jo check kare ki user authenticate hai ya nahi. Agar nahi, toh Navigate component se redirect kar do.

// components/RequireAuth.jsx import { Navigate, Outlet } from 'react-router-dom'; function RequireAuth() { // Check auth status (Redux se, Context se, ya LocalStorage se) const isAuthenticated = localStorage.getItem('token') ? true : false; if (!isAuthenticated) { // Redirect to login // replace=true lagana zaroori hai taaki user back button daba ke wapas yahan na aa sake return <Navigate to="/login" replace />; } // Agar login hai, toh uske children (jo route maanga tha) ko render hone do return <Outlet />; } export default RequireAuth;

6.2 Router mein Use Karna

Ab is RequireAuth ko apne router mein parent element bana do un routes ke liye jo private hain.

const router = createBrowserRouter([ // Public Routes { path: '/', element: <Home /> }, { path: '/login', element: <Login /> }, // Protected Routes (RequireAuth ke andar nest kiye) { path: '/dashboard', element: <RequireAuth />, // <-- Guard yahan laga hai children: [ { path: '', element: <DashboardHome /> }, // Sirf logged-in users ko dikhega { path: 'profile', element: <Profile /> }, // Sirf logged-in users ko dikhega { path: 'settings', element: <Settings /> } // Sirf logged-in users ko dikhega ] } ]);

Important: useNavigate ek function (hook) hai jo button clicks mein use hota hai. Navigate ek component hai jo render hote hi redirect kar deta hai. Auth guards mein hamesha component (Navigate) use karo.

TOPIC 07

Loaders & Actions (Modern APIs)

Yeh v6.4+ ka sabse powerful feature hai. Puraane tareeqe mein page load hota tha, spinner ghumta tha, fir data aata tha. Ab router route par jaane se *pehle* hi data fetch kar sakta hai!

7.1 Loaders — GET Data Before Render

// 1. Loader function define karo (Page ke bahar) export async function postsLoader() { const res = await fetch('https://api.example.com/posts'); if (!res.ok) throw new Error('Failed to load posts'); return res.json(); } // 2. Component mein data consume karo import { useLoaderData } from 'react-router-dom'; export function PostsPage() { // Yeh data route transition complete hone par hi available hoga // Koi loading state ki zaroorat nahi! const posts = useLoaderData(); return <div>{posts.map(p => <h3 key={p.id}>{p.title}</h3>)}</div>; } // 3. Router mein loader assign karo (main.jsx) { path: '/posts', element: <PostsPage />, loader: postsLoader, // Yahan joda }

7.2 Actions — Handle Form Submissions (POST/PUT)

Form submission bhi router handle kar sakta hai. Jab tum <Form> component (react-router-dom wala) submit karte ho, toh woh route ka action function run karta hai.

// 1. Action function export async function contactAction({ request }) { const formData = await request.formData(); const data = Object.fromEntries(formData); // { email: '...', message: '...' } await apiPost('/contact', data); return redirect('/success'); // Success ke baad bhej do } // 2. Component (Note: React Router wala
hai, HTML wala nahi) import { Form } from 'react-router-dom'; export function ContactPage() { // Koi event.preventDefault() ya state (useState) nahi chahiye! return ( <Form method="post"> <input type="email" name="email" required /> <textarea name="message" required></textarea> <button type="submit">Send</button> </Form> ); } // 3. Router mein { path: '/contact', element: <ContactPage />, action: contactAction }

Interview Fact: Actions aur Loaders ki wajah se "Render-as-you-fetch" approach milti hai, jisse Waterfalls problem (Render → Fetch → Render) solve ho jaati hai.

TOPIC 08

Error Handling & 404 Pages

Agar user galat URL daale, ya loader API fail ho jaaye, toh poori app crash nahi honi chahiye. React Router mein iske liye errorElement hai.

8.1 useRouteError Hook

Galat URL par ya exception aane par jo component render hoga (errorElement), usme error ki details useRouteError se mil sakti hain.

// pages/ErrorPage.jsx import { useRouteError, Link } from 'react-router-dom'; export default function ErrorPage() { const error = useRouteError(); console.error(error); return ( <div className="error-container"> <h1>Oops! Kuch galat ho gaya.</h1> {/* 404 Not Found error */} {error.status === 404 ? ( <p>Yeh page exist nahi karta.</p> ) : ( {/* Server errors or code throws */} <p>{error.statusText || error.message}</p> )} <Link to="/">Ghar Wapas Chalein</Link> </div> ); }

8.2 Global vs Specific Errors

const router = createBrowserRouter([ { path: '/', element: <MainLayout />, errorElement: <GlobalErrorPage />, // <--- GLOBAL ERROR (404s, etc) children: [ { path: 'products', element: <ProductsPage />, loader: productsLoader, // Agar sir product loader fail ho, toh sirf yeh page error dikhayega, // baaki website (navbar/footer) chalti rahegi! errorElement: <ProductErrorFallback /> } ] } ]);

Pro Tip: Nested errorElements ka faida yeh hai ki error jis level pe aaya hai, sirf wahi UI break hota hai. Parent layout intact rehta hai (jise "Error Boundaries" kehte hain).

TOPIC 09

Interview Questions & Cheat Sheet

9.1 Most Asked Interview Questions

Q1: Link aur <a href="..."> mein kya fark hai?

<a> tag browser ko naya page load karne pe majboor karta hai (full reload, SPA break). <Link> default behaviour prevent karke sirf browser ka URL update karta hai (History API) aur React ko naya component render karne bolta hai.

Q2: useNavigate vs <Navigate /> mein kya fark hai?

useNavigate ek hook hai jo ek function return karta hai, jise hum event handlers (onClick, onSubmit) mein call karte hain. <Navigate /> ek component hai jo render hote hi redirect karta hai, isliye ise declarative redirection (jaise auth guards) mein use karte hain.

Q3: Outlet kya hai aur kyun use hota hai?

Outlet ek placeholder hai jo parent route ke component ko batata hai ki child routes kahan render honge. Iske bina nested routing kaam nahi karegi aur shared layouts (Navbar/Footer) apply nahi honge.

Q4: useParams aur useSearchParams mein kya fark hai?

useParams dynamic path segments extract karta hai (e.g., /users/:id). useSearchParams query strings read aur modify karta hai (e.g., ?page=2&sort=asc) aur yeh useState ki tarah kaam karta hai.

Q5: v6.4+ mein Loaders kyun introduce kiye gaye?

Pehel "render → fetch (useEffect) → loading → render" cycle hoti thi jisse UI delays (waterfalls) aate the. Loaders se navigation shuru hote hi data fetch hota hai (Fetch-as-you-render), jab data ready ho tabhi page render hota hai.
