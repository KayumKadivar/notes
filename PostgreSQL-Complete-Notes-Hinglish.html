MODULE 01

Introduction to Databases

Bilkul sahi jagah aaye ho! Yeh ek structured, practical, aur interview-ready PostgreSQL course hai — seedha scratch se advanced tak. Har concept real-world perspective se cover hoga, taki sirf theory nahi, actual projects bhi build kar sako. Chalo shuru karte hain! 🚀

1.1 Concept Explanation — Database Kya Hai?

Socho tumhare paas ek school ka register hai jisme students ke naam, roll numbers, aur marks likhe hain. Yeh register ek manual database hai.

Database ek organized collection of data hai jo:

  • Efficiently store kiya ja sake
  • Easily retrieve kiya ja sake
  • Securely manage kiya ja sake

Types of Databases

Type Example Use Case
Relational (SQL) PostgreSQL, MySQL Structured data, tables
Document (NoSQL) MongoDB Flexible JSON data
Key-Value Redis Caching, sessions
Graph Neo4j Social networks
Time-Series InfluxDB IoT, metrics

1.2 Real-World Example — Zomato ka Socho!

👤 Users Tablenaam, email, address store hota hai
🏪 Restaurants Tablerestaurant info, menu, ratings
📦 Orders Tablekaunse user ne kaunse restaurant se order kiya — yeh RELATIONSHIP hai!

Yahi kaam ek Relational Database karta hai — data ko tables mein store karta hai aur unhe relationships se connect karta hai.

1.3 DBMS vs RDBMS

DBMS → Database Management System (e.g., file system)
RDBMS → Relational DBMS (data tables mein hota hai, relations hote hain)

DBMS RDBMS
Data files mein store hota hai Data tables mein store hota hai
Relations nahi hote Tables ke beech relations hote hain
e.g., XML files e.g., PostgreSQL, MySQL

Pro Tip: RDBMS prefer karo jab bhi data structured ho aur tables ke beech relationships ho — yeh data integrity aur performance dono ensure karta hai.

MODULE 02

What is PostgreSQL?

PostgreSQL (pronounced: post-gres-Q-L) ek open-source, object-relational database system hai. Isko "Postgres" bhi kehte hain.

2.1 Concept Explanation — PostgreSQL Kyun Special Hai?

  • Free & Open Source — koi license cost nahi
  • ACID Compliant — data safe rehta hai
  • JSON support — NoSQL features bhi hain (JSONB)
  • Advanced features — Window Functions, CTEs, aur bahut kuch
  • Highly extensible — custom data types bana sakte ho
  • Industry ka most trusted database — 35+ saal se use ho raha hai

2.2 Real-World Usage — Yeh Companies Use Karti Hain

Company Use Case
Instagram User data, posts, relationships
Spotify Music metadata, playlists
Uber Trip data, driver management
Apple iCloud data storage
Reddit Posts, comments, votes

2.3 PostgreSQL vs MySQL vs MongoDB

Feature PostgreSQL MySQL MongoDB
Type RDBMS RDBMS NoSQL
JSON Support ✓ Native JSONB ⚠ Limited ✓ Native
ACID ✓ Full ✓ Full ⚠ Partial
Performance 🔥 Complex queries ⚡ Simple reads ⚡ Flexible
Best For Complex apps Web apps Unstructured data

Pro Tip: Modern full-stack projects (Node.js, Next.js) mein PostgreSQL + Prisma combination sabse popular hai. Yeh combination production-ready apps ke liye best choice hai.

Installation & Setup

PostgreSQL install karna simple hai — Windows, macOS, aur Linux teeno par. Niche step-by-step guide hai, OS ke hisaab se.

3.1 Installation Steps

🪟 Windows

# Step 1: Download karo # https://www.postgresql.org/download/windows/ # Installer run karo aur yeh install hoga: # - PostgreSQL Server # - pgAdmin 4 (GUI tool) # - psql (command line tool) # Step 2: Installation ke time: # Port: 5432 (default - change mat karo) # Password: apna password set karo (yaad rakhna!) # Locale: Default

🍎 macOS

# Homebrew se install karo brew install postgresql@16 # Service start karo brew services start postgresql@16 # psql mein connect karo psql postgres

🐧 Linux (Ubuntu/Debian)

# Step 1: Repository update karo aur install karo sudo apt update sudo apt install postgresql postgresql-contrib # Step 2: Service start karo sudo systemctl start postgresql sudo systemctl enable postgresql # Step 3: postgres user mein switch karo sudo -i -u postgres # Step 4: psql open karo psql

3.2 First Time Setup

-- postgres user ka password set karo ALTER USER postgres PASSWORD 'mypassword123'; -- Apna pehla database banao CREATE DATABASE myFirstDB; -- Database list dekho \l -- Database mein connect ho \c myFirstDB -- Quit karo \q

3.3 pgAdmin Setup (GUI Tool)

Step 1pgAdmin 4 open karo (Windows mein Start Menu se)
Step 2Master Password set karo
Step 3Servers → PostgreSQL → Connect → Password enter karo
Step 4 ✓Ab tum GUI se database manage kar sakte ho!

Beginners ke liye: pgAdmin use karo visually samajhne ke liye. Baad mein psql aur code se karo — production mein hamesha command-line tools use hoti hain.

3.4 Common Mistakes

  • Port 5432 already in use → Dusri service band karo ya port change karo
  • Password bhool gaye → pg_hba.conf se reset kar sakte ho
  • Service start nahi hui → sudo systemctl status postgresql se check karo

PostgreSQL Architecture

PostgreSQL ke andar kya hota hai — ek SQL query kaise process hoti hai aur data kaise disk par save hota hai.

4.1 Architecture Overview

┌────────────────────────────────────────┐ │ CLIENT (psql / App Code) │ └─────────────────╬──────────────────────┘ | SQL Query ┌─────────────────╯──────────────────────┐ │ POSTMASTER PROCESS │ │ (Connection Manager - Traffic Cop) │ └─────────────────╬──────────────────────┘ | ┌─────────────────╯──────────────────────┐ │ BACKEND PROCESS │ │ ┌─────────────────────────────────┐ │ │ │ Parser -> Analyzer -> Planner │ │ │ │ -> Executor │ │ │ └─────────────────────────────────┘ │ └─────────────────╬──────────────────────┘ | ┌─────────────────╯──────────────────────┐ │ SHARED MEMORY │ │ ┌─────────────┐ ┌───────────────┐ │ │ │ Shared Buffer│ │ WAL Buffer │ │ │ │ (Cache) │ │ (Write-Ahead │ │ │ └─────────────┘ │ Logging) │ │ │ └───────────────┘ │ └─────────────────╬──────────────────────┘ | ┌─────────────────╯──────────────────────┐ │ DISK STORAGE │ │ ┌─────────┐ ┌────────┐ ┌────────┐ │ │ │ Data │ │ WAL │ │ Logs │ │ │ │ Files │ │ Files │ │ │ │ │ └─────────┘ └────────┘ └────────┘ │ └────────────────────────────────────────┘

Key Components

Component Kya Karta Hai
Postmaster Nayi connections accept karta hai — traffic cop ki tarah
Parser SQL query ko parse karta hai (syntax check)
Analyzer Semantic check karta hai (table exist karti hai?)
Planner/Optimizer Best execution plan choose karta hai
Executor Actually query run karta hai
Shared Buffer Data ko RAM mein cache karta hai (fast access)
WAL Crash recovery ke liye changes log karta hai

4.2 Real-World Analogy — Restaurant

PostgreSQL Component Restaurant Analogy
Postmaster Receptionist (customers ko table assign karta hai)
Parser Waiter (order samajhta hai)
Planner Chef ka plan (kaise banana hai decide karta hai)
Executor Chef (actually khana banata hai)
Shared Buffer Kitchen counter (ready items yahan rakhte hain)
WAL Order book (agar kuch gadbad ho to recover kar sako)
Disk Storage Cold storage (permanent storage)

Interview Fact: WAL (Write-Ahead Logging) ki wajah se PostgreSQL crash ke baad bhi data safe rehta hai. Pehle log likha jaata hai, phir data files update hote hain.

MODULE 05

psql Commands

psql PostgreSQL ka command-line interface hai. Yeh ek terminal tool hai jisse tum directly database se baat kar sakte ho — bina kisi GUI ke.

5.2 Essential psql Commands

-- CONNECTION COMMANDS -- PostgreSQL se connect karo psql -U postgres -h localhost -p 5432 -- Specific database se connect karo psql -U postgres -d mydb -- META COMMANDS (\ se start hote hain) \l -- Saare databases list karo \c dbname -- Database change/connect karo \dt -- Current database ki saari tables \d tablename -- Table ka structure dekho \du -- Saare users/roles list karo \dn -- Saare schemas list karo \df -- Saare functions list karo \timing -- Query execution time on/off \e -- External editor open karo \i file.sql -- SQL file execute karo \o file.txt -- Output file mein save karo \q -- psql se quit karo \? -- Help for meta commands \h SELECT -- SQL command ka help -- USEFUL SHORTCUTS \x -- Expanded display (wide tables ke liye) \a -- Output format toggle \pset border 2 -- Table borders set karo

5.3 Practical Session — Step by Step

-- Step 1: psql open karo psql -U postgres -- Step 2: Database banao CREATE DATABASE ecommerce_db; -- Step 3: Connect karo \c ecommerce_db -- Step 4: Confirm karo ki connected ho SELECT current_database(); -- Output: ecommerce_db -- Step 5: PostgreSQL version check karo SELECT version(); -- Step 6: Current time check karo SELECT NOW(); -- Step 7: Simple calculation SELECT 10 + 20 AS result; -- Output: 30

5.4 Common Mistakes

  • Semicolon (;) bhool gaye → Query execute nahi hogi, prompt mein -> dikhega
  • \q ke baad Enter nahi kiya → Quit nahi hoga
  • Case sensitivity → Table names lowercase mein rakho by default
  • Wrong database mein ho → \c se pehle \l se check karo

Yaad Rakho: psql mein semicolon (;) compulsory hai query end karne ke liye. Bina semicolon ke Enter dabane par psql multi-line input wait karta hai — aur beginners confuse ho jaate hain!

MODULE 06

Data Types

Data types define karte hain ki column mein kaunsa type ka data store hoga. Sahi type choose karna storage, validation aur performance ke liye zaroori hai.

6.1 Kyun Important Hai?

  • Storage optimize hoti hai — sahi type se kam space lagta hai
  • Data validation automatic hoti hai — galat data nahi ghus sakta
  • Performance better hoti hai — queries fast run karti hain

6.2 Numeric Types

-- INTEGER types SMALLINT -- -32,768 to 32,767 (2 bytes) INTEGER / INT -- -2.1B to 2.1B (4 bytes) <- Most common BIGINT -- Very large numbers (8 bytes) -- SERIAL (Auto-increment) SERIAL -- Auto-incrementing INT (4 bytes) <- Primary keys ke liye BIGSERIAL -- Auto-incrementing BIGINT (8 bytes) -- DECIMAL types DECIMAL(p,s) -- Exact decimal (p=precision, s=scale) NUMERIC(p,s) -- Same as DECIMAL REAL -- 6 decimal digits (4 bytes) DOUBLE PRECISION -- 15 decimal digits (8 bytes) -- Examples: price DECIMAL(10,2) -- 99999999.99 tak store kar sakta hai rating REAL -- 4.5, 3.7 etc.

6.3 Text Types

CHAR(n) -- Fixed length string (n characters) VARCHAR(n) -- Variable length, max n characters TEXT -- Unlimited length string <- Most flexible -- Examples: phone CHAR(10) -- Exactly 10 characters name VARCHAR(100) -- Max 100 characters description TEXT -- Koi bhi length

6.4 Date/Time, Boolean & Special Types

-- DATE/TIME TYPES DATE -- Only date: '2024-01-15' TIME -- Only time: '14:30:00' TIMESTAMP -- Date + Time: '2024-01-15 14:30:00' TIMESTAMPTZ -- Timestamp with timezone <- Production mein use karo INTERVAL -- Time interval: '2 hours', '3 days' -- BOOLEAN BOOLEAN -- TRUE / FALSE / NULL is_active BOOLEAN DEFAULT TRUE -- SPECIAL TYPES UUID -- Universally Unique ID JSON -- JSON data (text ke roop mein store) JSONB -- Binary JSON (faster, indexable) <- Prefer karo ARRAY -- Array of any type -- Examples: user_id UUID DEFAULT gen_random_uuid() metadata JSONB tags TEXT[] -- Array: ['electronics', 'mobile']

6.5 Real-World Example — E-commerce Table Design

CREATE TABLE products ( -- Identity product_id SERIAL PRIMARY KEY, sku VARCHAR(50) UNIQUE, -- Basic Info name VARCHAR(255) NOT NULL, description TEXT, -- Pricing price DECIMAL(10,2) NOT NULL, -- e.g., 1999.99 discount_pct REAL DEFAULT 0, -- e.g., 10.5 (%) -- Inventory stock_qty INTEGER DEFAULT 0, -- Flags is_active BOOLEAN DEFAULT TRUE, is_featured BOOLEAN DEFAULT FALSE, -- Metadata tags TEXT[], -- ['electronics', 'mobile'] attributes JSONB, -- {"color": "red", "size": "XL"} -- Timestamps created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW() );

6.6 Common Mistakes

-- WRONG: Price ke liye FLOAT use karna price FLOAT -- Floating point errors! 19.99 -> 19.989999999 -- CORRECT: DECIMAL use karo price DECIMAL(10,2) -- Exact value: 19.99 -- WRONG: Sab kuch VARCHAR mein store karna age VARCHAR(10) -- '25abc' bhi store ho jayega! -- CORRECT: Appropriate type use karo age INTEGER -- Only numbers allowed -- WRONG: TIMESTAMP without timezone created_at TIMESTAMP -- Timezone issues in production! -- CORRECT: created_at TIMESTAMPTZ DEFAULT NOW()

6.7 Best Practices

  • Primary keys ke liye SERIAL ya UUID use karo
  • Money ke liye hamesha DECIMAL use karo, kabhi FLOAT nahi
  • Timestamps ke liye TIMESTAMPTZ use karo (timezone-aware)
  • Long text ke liye TEXT use karo, VARCHAR sirf jab limit chahiye
  • Flags ke liye BOOLEAN use karo (0/1 nahi)
  • Flexible data ke liye JSONB use karo (JSON se faster)

MODULE 07

CRUD Operations

CRUD = Create, Read, Update, Delete — yeh 4 basic operations hain jo har database application mein use hote hain.

7.1 CRUD Kya Hai?

CREATEINSERT — data add karo
READSELECT — data padhho
UPDATEUPDATE — data modify karo
DELETEDELETE — data hatao

7.2 Practice Database Setup

CREATE DATABASE company_db; \c company_db CREATE TABLE employees ( emp_id SERIAL PRIMARY KEY, first_name VARCHAR(50) NOT NULL, last_name VARCHAR(50) NOT NULL, email VARCHAR(100) UNIQUE NOT NULL, department VARCHAR(50), salary DECIMAL(10,2), hire_date DATE DEFAULT CURRENT_DATE, is_active BOOLEAN DEFAULT TRUE );

7.3 CREATE — INSERT

-- SINGLE ROW INSERT INSERT INTO employees (first_name, last_name, email, department, salary) VALUES ('Rahul', 'Sharma', 'rahul@company.com', 'Engineering', 75000.00); -- MULTIPLE ROWS INSERT (Efficient!) INSERT INTO employees (first_name, last_name, email, department, salary) VALUES ('Priya', 'Patel', 'priya@company.com', 'Marketing', 65000.00), ('Amit', 'Kumar', 'amit@company.com', 'Engineering', 80000.00), ('Neha', 'Singh', 'neha@company.com', 'HR', 55000.00), ('Ravi', 'Gupta', 'ravi@company.com', 'Engineering', 90000.00), ('Sita', 'Verma', 'sita@company.com', 'Marketing', 60000.00), ('Arjun', 'Mehta', 'arjun@company.com', 'Finance', 70000.00), ('Kavya', 'Reddy', 'kavya@company.com', 'Engineering', 85000.00), ('Rohit', 'Joshi', 'rohit@company.com', 'HR', 52000.00); -- INSERT WITH RETURNING (inserted data wapas lo) INSERT INTO employees (first_name, last_name, email, department, salary) VALUES ('Deepa', 'Nair', 'deepa@company.com', 'Finance', 68000.00) RETURNING emp_id, first_name, email; -- Output: emp_id=10, first_name='Deepa', email='deepa@company.com'

7.4 READ — SELECT

-- BASIC SELECT SELECT * FROM employees; SELECT first_name, last_name, salary FROM employees; -- Column alias SELECT first_name AS "First Name", last_name AS "Last Name", salary AS "Monthly Salary" FROM employees; -- WHERE CLAUSE (filtering) SELECT * FROM employees WHERE department = 'Engineering'; SELECT first_name, salary FROM employees WHERE salary > 70000; -- AND condition SELECT * FROM employees WHERE department = 'Engineering' AND salary > 75000; -- OR condition SELECT * FROM employees WHERE department = 'HR' OR department = 'Finance'; -- ORDER BY SELECT first_name, salary FROM employees ORDER BY salary DESC; -- Multiple column sort SELECT first_name, department, salary FROM employees ORDER BY department ASC, salary DESC; -- LIMIT & OFFSET (pagination) SELECT * FROM employees LIMIT 3; SELECT * FROM employees ORDER BY emp_id LIMIT 3 OFFSET 3; -- DISTINCT SELECT DISTINCT department FROM employees; -- LIKE (pattern matching) SELECT * FROM employees WHERE first_name LIKE 'R%'; SELECT * FROM employees WHERE email LIKE '%company%'; SELECT * FROM employees WHERE first_name LIKE '____'; SELECT * FROM employees WHERE first_name ILIKE 'rahul'; -- case-insensitive -- IN / NOT IN SELECT * FROM employees WHERE department IN ('Engineering', 'Finance'); SELECT * FROM employees WHERE department NOT IN ('HR'); -- BETWEEN SELECT * FROM employees WHERE salary BETWEEN 60000 AND 80000; -- IS NULL / IS NOT NULL SELECT * FROM employees WHERE department IS NULL; SELECT * FROM employees WHERE department IS NOT NULL;

7.5 UPDATE

-- Rahul ki salary badhao UPDATE employees SET salary = 80000.00 WHERE email = 'rahul@company.com'; -- Multiple columns update UPDATE employees SET salary = 95000.00, department = 'Senior Engineering' WHERE emp_id = 4; -- Calculated update: Engineering ko 10% raise UPDATE employees SET salary = salary * 1.10 WHERE department = 'Engineering'; -- UPDATE WITH RETURNING UPDATE employees SET salary = salary * 1.05 WHERE department = 'HR' RETURNING emp_id, first_name, salary AS new_salary;

7.6 DELETE

-- Specific row delete DELETE FROM employees WHERE emp_id = 8; -- Inactive employees delete DELETE FROM employees WHERE is_active = FALSE; -- DELETE WITH RETURNING DELETE FROM employees WHERE department = 'HR' AND salary < 53000 RETURNING *; -- SAARI ROWS DELETE (CAREFUL!) DELETE FROM employees; -- Saari rows delete, table rahegi TRUNCATE TABLE employees; -- Faster, saari rows delete, auto-increment reset

7.7 Expected Output

emp_id | first_name | department | salary --------+------------+-------------+---------- 5 | Ravi | Engineering | 99000.00 <- 10% raise ke baad 7 | Kavya | Engineering | 93500.00 <- 10% raise ke baad 3 | Amit | Engineering | 88000.00 <- 10% raise ke baad 1 | Rahul | Engineering | 80000.00 <- Updated manually 6 | Arjun | Finance | 70000.00 10 | Deepa | Finance | 68000.00 2 | Priya | Marketing | 65000.00 6 | Sita | Marketing | 60000.00 4 | Neha | HR | 57750.00 <- 5% raise ke baad

7.8 Common Mistakes

-- DANGEROUS: WHERE clause bhool gaye UPDATE mein UPDATE employees SET salary = 0; -- Saare employees ki salary 0 ho gayi! -- SAFE: Hamesha WHERE use karo UPDATE employees SET salary = 0 WHERE emp_id = 999; -- DANGEROUS: WHERE clause bhool gaye DELETE mein DELETE FROM employees; -- Saara data chala gaya! -- SAFE: DELETE FROM employees WHERE emp_id = 999; -- PRO TIP: Pehle SELECT karo, phir UPDATE/DELETE SELECT * FROM employees WHERE department = 'HR'; -- Sahi lag raha hai? Phir delete karo: DELETE FROM employees WHERE department = 'HR';

DELETE vs TRUNCATE: DELETE row-by-row karta hai aur WHERE clause support karta hai. TRUNCATE saari rows ek saath delete karta hai, bahut fast hota hai, aur auto-increment reset karta hai!

7.9 Best Practices

  • UPDATE/DELETE se pehle hamesha SELECT karo
  • RETURNING clause use karo confirmation ke liye
  • Transactions use karo important operations mein
  • Table clear karne ke liye TRUNCATE use karo — DELETE se faster
  • Soft delete prefer karo — is_active = FALSE — data recover ho sake

Practice Questions

CRUD operations ko solid banane ke liye yeh questions solve karo — easy se hard tak.

Easy Level

  • Saare employees ka naam aur department select karo
  • Sirf 'Finance' department ke employees dikhao
  • Salary ke hisaab se ascending order mein sort karo

Medium Level

  • 60000 se 80000 ke beech salary wale employees dikhao
  • Email mein 'company.com' wale employees find karo
  • Top 3 highest paid employees dikhao

Hard Level

  • Marketing department ke saare employees ki salary 15% badhao
  • Pehle 5 employees ko page 1, agle 5 ko page 2 mein dikhao
  • Unique departments ki list nikalo with employee count

Interview Questions

Q1: DELETE aur TRUNCATE mein kya difference hai?
DELETE TRUNCATE
Row by row delete karta hai Saari rows ek saath delete
WHERE clause support karta hai WHERE clause nahi hota
ROLLBACK possible hai PostgreSQL mein ROLLBACK possible
Triggers fire hote hain Triggers fire nahi hote
Slower for large data Much faster
Q2: SELECT * use karna kab avoid karna chahiye?
  • Unnecessary data transfer hoti hai — network slow
  • Schema change hone par code break ho sakta hai
  • Index coverage nahi milti — query slow
Q3: RETURNING clause kab use karte hain?

Jab INSERT/UPDATE/DELETE ke baad turant affected rows ka data chahiye ho — extra SELECT query ki zaroorat nahi padti. APIs mein naya ID return karne ke liye useful.

Pro Tip: RETURNING clause PostgreSQL-specific feature hai — MySQL mein LAST_INSERT_ID() aur SQL Server mein OUTPUT clause use karte hain.
